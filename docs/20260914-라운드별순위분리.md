# 예선·본선·결선 순위 조회 분리

## 원인

순위 화면은 `goRankingByCode`에 전달된 라운드를 제목에만 사용했습니다. 실제 API 호출에는 조회 라운드가 없었으며 응답 전체를 표시했습니다. 정상 응답 캐시도 대회코드만으로 재사용해 결선 조회 중 예선 순위가 보일 수 있었습니다.

배포 전 읽기 전용 점검에서 운영 점수 행 837건은 모두 예선으로 저장되어 있었고, 라운드 누락은 0건이었습니다. 본선·결선으로 데이터가 옮겨진 문제가 아니라 조회 범위의 문제였습니다.

## 수정

- 모든 대회의 순위 API 호출에 정확한 조회 라운드를 전달하고 서버·브라우저 양쪽에서 필터링합니다.
- 캐시를 대회코드 + 라운드로 분리합니다. 새 라운드 조회 실패 시 다른 라운드의 순위를 대신 표시하지 않습니다.
- 순위 화면에 조회 라운드 선택과 새로고침을 제공합니다. 이 선택은 운영 라운드/대회 공개 설정을 변경하지 않습니다.
- 빈 본선·결선에는 해당 라운드에 집계된 평가가 없음을 표시합니다.
- 순위 상세는 참가자번호와 라운드를 함께 지정해야 합니다. 늦게 도착한 이전 상세 응답은 무시합니다.
- 순위 PDF와 최종디브리핑 엑셀은 선택한 라운드로 한정합니다. 전체 점수·검수 백업은 기존처럼 전체 기록을 유지합니다.
- 기존 전체 라운드 API 소비자와 백업 호환성을 위해 라운드 인자를 생략한 종전 조회 계약은 유지합니다.
- IKRC 팀장 카드에 없는 검수 버튼을 연결하다 발생할 수 있는 오류도 방어했습니다.

## 데이터 보호 및 검증

- 점수 계산식, 점수/코멘트 원본, 선수정보, 심사위원 권한, 대회 공개 상태, 운영 라운드는 변경하지 않습니다.
- 실제 RPC를 로컬 SQLite에 연결해 7개 대회의 동일 심사위원·참가자번호로 예선/본선/결선을 각각 제출했습니다.
- 라운드별 저장·순위·상세·엑셀 응답, 빈 결선, 켈리브레이션 제외, 오래 열린 예선 화면 제출 거부, 검수 수정의 타 라운드 비간섭을 검증합니다.
- 관리자와 실제 팀장 로그인으로 360/768/1440px 순위 버튼·라운드 선택·상세·새로고침·출력 범위를 검증합니다.
- 통신 실패, 이전 캐시, 역순 응답, 구버전 전체 라운드 응답, 늦은 상세 응답을 별도로 재현합니다.
- 기존 회귀 94개 실행 명령과 전체 화면/결선/검수-디브리핑 브라우저 테스트를 수행합니다.

## 운영 안내

배포 후 순위 화면을 새로 열고 상단의 **조회 라운드**를 선택합니다. 본선·결선 평가 전에는 빈 목록이 정상입니다. 기존 예선 기록은 **예선**을 선택하면 그대로 조회됩니다.
