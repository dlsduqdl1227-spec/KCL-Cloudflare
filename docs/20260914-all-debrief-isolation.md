# 전체 대회 디브리핑 연결 검수

## 적용 내용

- 7개 대회 모두 대회 코드, 라운드, 실제 참가번호로만 선수 기록을 조회합니다.
- 내부 DB ID, 코멘트에 포함된 숫자, 임의 메타데이터의 부분 이름 검색을 디브리핑에서 제거했습니다.
- 선수명과 등록 연락처를 함께 확인합니다. KTCC는 등록 팀명과 명시된 팀원 이름을 지원하며 등록된 팀 연락처를 사용합니다.
- IKRC는 라운드별 블라인드코드를 유지합니다. 원래의 헤드·센서리 구성, 공식 점수와 평균 계산은 변경하지 않습니다.
- 본선 번호를 예선 번호로 처리하던 선수 정보 조회와 다른 라운드로의 대체 검색을 수정했습니다.
- 관리자 미리보기와 선수 화면은 같은 서버 함수를 사용합니다. 동일 번호가 서로 다른 선수에게 배정됐으면 잘못된 결과를 보여주지 않고 배정 확인 안내를 반환합니다.
- 선수에게 응답하는 점수에는 다른 선수 기록이 포함될 수 있는 원본 일괄 제출 payload를 제외합니다. 본인 평가 행의 점수·스마트태그·코멘트는 유지합니다.
- 여러 라운드 기록이 있으면 라운드별 순위와 점수를 각각 표시합니다.

## 검증 범위

운영 DB는 읽기 전용으로 가져와 임시 SQLite에서 대조했습니다. 실제 선수에게 인증 문자를 보내거나 운영 DB에 테스트 점수를 저장하지 않았습니다.

- 등록 명단 615건, 원본 점수 837건을 대상으로 대회별 연결 조건 점검.
- 연락처가 있는 613건: 실제 OTP 검증 함수와 관리자 미리보기의 점수·순위 객체 전수 비교. 타인/타 라운드 연결 및 중복 배정 충돌 없음.
- 연락처가 없는 등록 항목 2건은 실제 본인인증 확인 불가. 명단을 임의로 변경하지 않았습니다.
- 모든 대회의 기존 순위·점수·평균·실격 여부 계산값이 변경 전과 일치.
- 인위적인 내부 ID 충돌, 이름 부분 일치, 동일 번호의 다른 라운드 재사용, 번호 중복 배정, 기록 없음, 비공개 설정, IKRC 일괄 제출 데이터 노출을 회귀 테스트로 확인.
- 7개 대회 각각 390/768/1440px 브라우저에서 미리보기·선수 평가 영역 일치, 라운드 표시, JavaScript 오류와 화면 넘침 검사.

데이터베이스 마이그레이션은 없습니다. 원본 평가, 선수 명단, 운영 및 공개 설정을 변경하지 않습니다.

## 재실행

`npm run test:debrief-isolation`

`npm run test:moc-debrief`

브라우저 테스트는 Playwright가 필요하며 `KCL_PLAYWRIGHT_MODULE`로 설치 경로를 지정할 수 있습니다.
