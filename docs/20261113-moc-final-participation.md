# 2026-11-13 MOC 결선 참가 표시

사용자가 지정한 기존 MOC 선수 10명을 결선 참가자로 표시한다. 제공한 순서는 이미 나온 결선 최종 순위이며 번호 재배정이나 순위 수정 지시로 사용하지 않는다. 실제 선수 명단은 공개 소스에 포함하지 않는다.

배포에 포함된 고정된 일회성 데이터 보정은 기존 MOC 선수 중 이름이 각각 한 건으로 확인될 때만 진행한다. 선수를 생성하지 않으며 다른 대회·선수는 바꾸지 않는다. 기존 결선 번호가 있으면 보존한다. 비어 있으면 해당 선수의 기존 결선 평가 번호 또는 기존 본선/참가 번호를 연결한다. 제공한 순위로 새 번호를 만들지 않는다.

`lib/moc-final-registration.mjs`는 참가자·평가 식별 정보의 스냅샷을 대조한 원자적 D1 배치로 결선 번호가 비어 있는 대상만 갱신한다. 점수, 최종 순위, 예선·본선 번호, 연락처, 소속, 메모, 경연순서, 일정과 대회 운영 설정은 변경하지 않는다. 누락·동명이인·번호 충돌·동시 수정이 있으면 일부만 적용하지 않고 전체를 보류한다.

`functions/api/_middleware.js`는 운영 도메인의 기존 RPC 요청에서만 일회성 계획의 무작위 비밀 nonce를 포함한 전체 내용이 소스에 고정된 SHA-256 검증값과 정확히 일치할 때만 보정을 적용한다. 명단과 nonce는 운영 서버의 HTTPS 요청에만 전달하며 공개 저장소에 남기지 않는다. 미리보기, 다른 출처, 상태 조회 및 진단 API는 보정을 실행하지 않는다. SQL이나 임의 변경을 실행하는 API 및 새로운 관리자 역할을 만들지 않는다. 검증값은 임의 명단을 승인하지 않으며, nonce가 공개되지 않아 이름 사전 대입으로 명단을 추정할 수도 없다.

이전 결선 번호와 수정 시각은 D1 내부 `system_settings`의 `moc_final_participants_20261113_v1` 처리 기록에 보관한다. 적용 후에는 같은 작업을 반복하지 않으며 운영자의 이후 변경도 덮어쓰지 않는다. 운영 진단은 완료 여부만 확인하고 선수 정보나 처리 기록을 로그·첨부 결과에 내보내지 않는다.

검증: `tests/stage296-moc-final-registration.test.mjs`의 9개 사례와 기존 전체 API 검사. 운영 반영 후 소스 지문과 Cloudflare 배포 커밋을 확인하고, 검증된 일회성 계획과 함께 설정 조회로 보정이 실행된 뒤 읽기 전용 운영 진단을 다시 확인한다.

## KBC 결선 역순 배치

기존 결선 6명의 현재 시연순서를 뒤집어 사용자가 지정한 첫 시연자이 첫 번째가 되도록 한 번만 적용한다. 사용자가 지정한 첫 시연자이 이미 첫 번째면 다시 뒤집지 않는다. 마지막도 첫 번째도 아니거나 명단이 불완전하면 전체 보류한다. 기존 시간표의 첫 번째 슬롯부터 차례대로 배치하고, 선수 번호·평가·개인 메모·다른 라운드의 일정은 보존한다. 원래 일정은 내부 처리 기록 `kbc_final_order_20261113_reverse_v1`에 보관한다. 원자적 배치와 동시 변경 방어는 MOC와 같은 원칙으로 적용한다.

## KBC 프레젠테이션 디브리핑

기존 `Service Professionalism(서비스의 전문성)` 수치가 공개 점수 항목의 표시 조건에서 누락되어 있었다. KBC에 한해 이 항목과 예전 프레젠테이션 표기를 5점 만점 항목으로 표시하고, 관련 스마트태그와 작성 코멘트에 프레젠테이션·서비스 라벨을 붙인다. 저장된 점수나 순위 계산은 바꾸지 않는다. 다른 대회의 표시 규칙도 유지한다.

검증 범위에는 결선 역순·동시 수정·재실행 검사, KBC 점수 필터 검사, 390px/1440px 화면에서 예선·본선·결선과 운영자 미리보기·선수 공개 화면의 프레젠테이션 점수·태그·코멘트 검사가 포함된다.
