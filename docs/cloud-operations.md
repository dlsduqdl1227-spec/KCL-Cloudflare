# 운영 점검과 배포

## 즉시 작업 경로

1. 연결된 GitHub에서 `main`의 최신 커밋과 진행 중인 작업을 확인한다.
2. 전체 저장소를 체크아웃하고 Node 24, pnpm 10.11.1로 준비한다. 토큰이 없는 경우에도 공개 저장소 읽기와 연결된 GitHub 수정·기존 Pages 배포가 가능하다.
3. 관련 코드 수정 후 `pnpm test`, 필요한 브라우저 검사를 실행한다. 점수 산식 변경은 해당 대회 원문과 회귀 사례를 먼저 확인한다.
4. `ops/…` 브랜치에 먼저 반영하고 KCL Cloud 검사와 Pages 미리보기 결과를 확인한다.
5. 검증된 커밋을 `main`에 반영하고 그 커밋의 Cloudflare Pages `completed/success`를 확인한다. `/api/health`의 `release.commit`과 `/ops-build.json`도 대조한다.
6. GitHub Actions `live-audit` 결과를 확인한다. 추후 모바일 지시에서는 최근 main의 해당 작업을 재실행할 수 있다. 새 배포가 필요하지 않은 조회에도 이 경로를 사용한다.

| KCR | 원문 점수 권위, 컵·스테이션·라운드 격리, 수정·반려, 디브리핑 |

추가 공통 검사: 권한 위조·교차 대회 접근, 제출 재시도·동시 요청, 입력 보존, 모바일 너비·스크롤·버튼, JSON 응답 오류·로딩 실패, 예선/본선/결선 보고서, 운영 진단 인증.

## 데이터 보호

- 전체 검사는 로컬 가상 SQLite와 가상 계정으로 실행한다. 실제 대회에 테스트 점수를 제출하지 않는다.
- 운영 진단 함수는 SELECT만 사용한다. 공개 보고에는 이름·연락처·개별 점수·코멘트·샘플 번호를 남기지 않는다.
- 이미 발표한 KCAC 순위와 저장된 공식 확정점수는 진단 시 그대로 보존한다.
- 과거 평가 중복 기록은 삭제하지 않는다. IKRC 순위에는 선택한 한 기록만 들어가는지 검사한다.
- 운영 D1 초기화·마이그레이션·기존 명단 갱신 스크립트를 설치/배포에 추가하지 않는다.

## 자동 진단 인증

`/api/operations`는 GitHub OIDC의 RS256 서명, 고정 발급자·JWKS·대상 주소, 저장소 ID `1283722078`, 소유자 ID `240860836`, `main`, 지정된 `kcl-cloud.yml`, GitHub 호스팅 실행기, push/수동 실행 및 15분 이하 토큰을 검증한다. PR·포크·다른 브랜치·다른 워크플로·외부 재사용 워크플로는 거부한다. 영구 비밀키나 관리자 권한은 발급하지 않는다. API가 허용하는 동작은 지정한 대회의 익명 집계 진단뿐이다.

기존 관리자/대회팀장 세션의 `getCompetitionOpsAudit` RPC도 같은 진단 함수를 호출하며 대회 권한을 확인한다.

## 결과 해석

- `error`: 잘못된 JSON, 중복 순위 항목, 비수치 순위, IKRC 헤드 포함 또는 센서리 인원 불일치 등. 원문 조사 대상으로 보고한다.
- `warning`: 선택한 과거 평가의 참조가 사라진 상태 등. 기록을 자동 교체하지 않는다.
- `info`: 저장된 공식 확정점수 보존 또는 IKRC 결선의 과거 확정점수 제외 등 의도된 정책.
- `not_started`: 해당 라운드 기록 없음. 장애로 처리하지 않는다.
- `awaitingReview`, `incompletePanels`: 아직 완료되지 않은 운영 상태. 대회 진행 중일 수 있으므로 수치만으로 오류라고 말하지 않는다.

검사 통과는 정의된 회귀 사례와 진단 항목의 통과다. 모든 실제 수기 평가와 디지털 입력이 일치한다는 보장은 별도 원문 대조가 필요하다.
